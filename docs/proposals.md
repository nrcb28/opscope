# Cobertura de las propuestas del PDF

Esta tabla relaciona los **60 identificadores** del inventario de requisitos con código y comandos existentes. «Implementado» describe una capacidad local comprobable; no afirma que se haya ejecutado contra una suscripción, cuenta cloud, servicio de tickets o registro de paquetes real. «Parcial» identifica criterios que todavía no cubre la implementación. Las pruebas cloud y de entrega usan transportes simulados.

La CLI comparte [Core](../src/Opscope.Core), [Reporting](../src/Opscope.Reporting), [Evidence](../src/Opscope.Evidence), [Cloud](../src/Opscope.Cloud), [Api](../src/Opscope.Api) e [Integrations](../src/Opscope.Integrations). La ayuda ejecutable es `opscope --help`. La recolección local funciona sin credenciales cloud, servidor, agentes instalados ni envío externo.

## Azure

El módulo requiere Azure CLI instalada en una ubicación admitida, autenticación previa y permisos de lectura sobre los ámbitos elegidos. Resource Graph y cada servicio consultado deben estar disponibles para esa identidad. Reader/Monitoring Reader son puntos de partida que deben verificarse por API; no se afirma que cubran todos los clientes. No se inicia sesión, habilitan servicios, ejecuta Run Command ni recuperan secretos.

| ID | Implementación y uso | Prerrequisitos, verificación y límites |
| --- | --- | --- |
| AZ-01 | **Parcial.** `azure metadata`, `AzureMetadata` y autenticación existente de Azure CLI. | IMDS se consulta sin persistir tokens. No existe integración directa `DefaultAzureCredential`/`Azure.Identity`; una identidad administrada debe estar configurada en la CLI por el operador. Vincular evidencia local y recurso sigue siendo explícito. |
| AZ-02 | **Implementado.** `azure inventory --subscription <id>`: VMs, discos, NICs, IPs públicas, NSGs y recursos Arc mediante Resource Graph. | Paginación y proyecciones permitidas; hasta 10.000 filas por consulta. Cifrado del sistema invitado y protección completa requieren evidencia adicional. Defender debe existir y ser visible; no se activa. |

## AWS

El módulo requiere AWS CLI v2 en ubicación admitida y perfiles/cadena de credenciales ya configurados, preferentemente SSO o roles. IAM debe permitir las llamadas Describe/Get/List utilizadas; Security Hub, GuardDuty, SSM y CloudTrail solo se consultan si existen y la identidad tiene acceso. AWS Health puede exigir un plan de soporte concreto. Los costes y condiciones deben verificarse antes de usar cada servicio.

| ID | Implementación y uso | Prerrequisitos, verificación y límites |
| --- | --- | --- |
| AWS-01 | **Implementado mediante perfiles CLI.** `--profile`, `--profiles`, `--regions`; `AwsMetadataClient` utiliza exclusivamente IMDSv2 y mantiene el token en memoria. | Roles entre cuentas se configuran en perfiles AWS CLI. `--role-arn` directo no obtiene credenciales temporales y devuelve cobertura no disponible. No hay SDK AWS embebido ni prueba de autenticación real. |
| AWS-02 | **Implementado.** `aws inventory`: EC2, EBS, VPCs, interfaces, Elastic IPs y security groups. | APIs Describe con proyecciones, procedencia y respuesta acotada. AWS Config/Resource Explorer no son obligatorios ni fuentes implementadas. |
| AWS-03 | **Implementado con alcance definido.** `aws posture`: SG abiertos, EBS sin cifrar, `HttpTokens=optional`, S3 y findings existentes de Security Hub/GuardDuty. | Los controles S3 de cuenta/access points y AWS Config no se evalúan. No se infiere acceso efectivo completo ni se permite IMDSv1 para consultar metadatos. |
| AWS-04 | **Implementado.** `aws patches`: nodos SSM, estado de conexión y último cumplimiento de parches. | No gestionados, resultados ausentes y evaluación antigua se distinguen. No inicia Scan, Install, Run Command ni activaciones híbridas. |
| AWS-05 | **Implementado.** `aws health`: status checks EC2, alarmas CloudWatch y eventos AWS Health. | Cobertura de Health depende del contrato/permisos; fallos se informan por fuente. No se validaron llamadas con una cuenta real. |

## Verificación disponible

[CI](../.github/workflows/ci.yml) configura la compilación de la CLI y descubre todos los proyectos de regresión .NET en Linux, Windows y macOS. Los trabajos de navegador Ubuntu/Windows instalan las dependencias bloqueadas de Playwright con `npm ci` y Chromium con sus dependencias del SO; ejecutan solo el servidor local de fixtures, sin credenciales cloud ni envíos a terceros. Las pruebas Python de la CLI se ejecutan tras compilar en cada SO; cubren exportaciones, códigos de salida, custodia, hashes de traspaso y servidor loopback real. Los controles de acceso, redacción, parsers, firmas, cifrado, manipulación del bundle, SQLite y contratos usan pruebas reproducibles. Las pruebas de navegador conservan capturas/resultados solo como artefactos locales de prueba.

La comprobación real de permisos cloud, servicios habilitados, precios, contratos de API de cada cliente, certificados de firma, canales de paquetes y experiencia nativa macOS/Windows requiere los entornos correspondientes. Ninguna consulta de Opscope activa esos servicios o convierte una fuente no disponible en un resultado conforme.
